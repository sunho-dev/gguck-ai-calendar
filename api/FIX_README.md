## 실행 및 배포

기존 구조를 유지했습니다. gguck와 gguck/gguck-complete 양쪽 앱 소스에 같은 수정을 반영했습니다.
현재 Vercel Root Directory가 가리키는 위치를 유지하고 그 위치의 파일을 반영하세요.
두 폴더를 새로 중첩해서 추가하지 마세요. gguck-complete 안에 gguck-complete를 또 넣지 않습니다.
GitHub에서 현재 배포 브랜치에 변경 파일을 반영한 뒤 새 배포를 실행하세요.
이 수정본은 GitHub 푸시나 Vercel 배포를 자동 실행하지 않습니다.

VS Code에서는 실행할 폴더의 package.json을 기준으로 터미널을 열고 다음을 실행합니다.

```powershell
npm.cmd ci
npm.cmd run typecheck
npm.cmd test
npm.cmd run web
```

Vercel: Build Command `npm run build`, Output Directory `dist`.
API는 Expo 개발 서버만으로 실행되지 않습니다. 실제 AI·Google·푸시는 환경변수가 설정된 배포에서 확인합니다.

## 수정 내용

1. 기간제 규칙 차단: 일주일간·이번 주만·특정 날짜까지 등은 입력/API/저장 검증에서 거절합니다. 기간을 제거해 상시 규칙으로 저장하지 않습니다. AI 프롬프트도 동일 정책을 적용합니다.
2. 상시 규칙 유지: 주 3회 이하, 운동 다음 날 휴식 등은 유지합니다.
3. AI 오류 안내: '한국어 확인 질문' 같은 지시문이 그대로 표시되지 않게 처리하고, 서버 장애·요청 한도·지원 불가를 구분합니다. 해석 요청 시간 제한을 추가합니다.
4. 입력 보존: 규칙 저장 실패 시 초안을 지우지 않습니다. 해석 중 문장 수정·중복 요청을 막아 오래된 응답이 다른 문장에 적용되지 않도록 합니다.
5. 저장 결과: 화면 상단에서 저장 성공·실패를 볼 수 있습니다.
6. 시작 시각 알림: 정각 동기화가 미발송 알림을 삭제하지 않도록 최대 15분 유예를 둡니다. 일정 종료보다 늦게 발송하지 않습니다.
7. 재동기화: 이미 발송된 알림을 다시 대기열에 넣지 않습니다. 같은 브라우저의 동기화·해제 요청을 순서대로 처리합니다.
8. 기기 알림: 재연결 시 구독을 갱신하고 서버 오류 내용을 표시합니다. 연결 실패 후에도 실제 연결 상태를 다시 표시합니다.
9. 알림 미리보기: 실제 푸시와 같은 기본 문구를 사용합니다.

기존 일정 해석 및 Google API 파일과 gemini-3.6-flash 모델은 그대로 보존했습니다.
새 기능으로 기간제 규칙을 추가하지 않았습니다.
