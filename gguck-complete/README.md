복원 후 엔진/통합/회귀 테스트 총 90개, TypeScript 검사, Expo 웹 export를 확인했습니다. 브라우저 자동 조작은 실행 파일 다운로드 실패로 완료하지 못했습니다. 실제 Gemini/Google 연동과 WebMCP 실브라우저 동작은 별도 확인이 필요합니다.

업로드한 `gguck-main.zip`(GitHub snapshot `9334ee2ef23d4f89aad32cb8bc689d46986e80b3`)의 Expo/React Native Web 구조에 일정 비서와 규칙·알림 기능을 통합했습니다. 기존 월간/주간 캘린더, 디자인 컴포넌트, Gemini/Vercel API, Google 연결 코드를 유지합니다. GitHub에는 아직 커밋·푸시하지 않았습니다.

## VS Code에서 실행 (Windows)

Node.js 22.13 이상을 사용하세요. Expo SDK 57의 최소 Node 버전에 맞췄습니다.
공식 문서: https://docs.expo.dev/versions/v57.0.0/

1. 이 ZIP을 압축 해제합니다.
2. VS Code → 파일 → 폴더 열기 → **package.json이 들어 있는 gguck-main 폴더**를 엽니다.
3. VS Code 터미널에서 실행합니다.

```powershell
npm.cmd ci
npm.cmd run web
```

`C:\Users\jch44`에서 실행하면 package.json을 찾지 못합니다. 반드시 압축을 푼 프로젝트 폴더에서 실행하세요. macOS/Linux에서는 `npm`을 쓰면 됩니다.

```sh
npm test
npm run typecheck
npm run build
```

## Vercel 및 API

- Vercel 빌드 명령: `npm run build`, 출력 폴더: `dist`. 루트 `api/`의 기존 Vercel Functions를 사용합니다.
- `npm run web`은 Expo 화면만 실행합니다. `/api/interpret`와 Google OAuth/Calendar API는 함께 실행되지 않습니다. 간단한 문장·반복·취소는 로컬 규칙으로 실행할 수 있습니다.
- 실제 Gemini 및 Google API를 시험하려면 기존 `.env.example`의 서버 환경변수를 Vercel에 설정하고 별도 테스트 배포를 사용하세요. 키를 클라이언트 코드나 `EXPO_PUBLIC_` 변수에 넣지 마세요.
- 현재 프로젝트의 Google 인증은 `userId: local`을 공통으로 사용합니다. **여러 사용자가 쓰는 공개 서비스에 Google 연결을 열기 전에 사용자별 인증 세션과 서버 권한 검사가 필요합니다.** 이 통합에서 실제 Google 계정 연결·배포를 수행하지 않았습니다.
- Gemini 모델은 기존 설정을 유지했습니다. 실제 계정의 모델 이용 가능 여부와 API 응답은 확인하지 않았습니다.

## 반영한 기능

### 일정 등록

일정 비서에서 `내일 오후 8시 집에서 운동` → 일정 등록. 명확하고 규칙을 통과하면 바로 저장합니다. 8시의 오전/오후, 불확실한 AI 응답, 충돌이 있을 때만 팝업에서 확인합니다. 소요 시간 기본값은 60분입니다.

캘린더 빠른 입력은 일정 비서로 문장을 전달합니다. 기존 일정의 수정 및 .ics 내보내기는 유지했습니다. 초기 화면에 가짜 샘플 일정을 새로 삽입하지 않으며 기존 저장 데이터는 그대로 읽습니다.

### 반복

`매일 오전 9시 공부`, `평일 오전 9시 업무`, `매주 월수금 오후 8시 운동`, `매월 25일 오후 6시 월세 납부`를 지원합니다. 반복은 시작일 미지정 시 내일을 기준으로 잡고 기본 4주, 종료일을 변경하면 최대 1년까지 설정할 수 있습니다. 전체 회차 검사 후 충돌한 날짜를 직접 건너뛰거나 입력을 수정해야 합니다. 없는 월 날짜(2월 31일 등)는 건너뜁니다.

각 회차는 공통 seriesId를 가진 별도 이벤트입니다. Google에도 개별 이벤트로 보냅니다. Google 자체의 RRULE 반복 시리즈를 만드는 방식은 아닙니다.

### 문장으로 취소

`내일 운동 취소`, `종숲 취소`, `운동 전체 반복 취소`. 카드의 삭제 버튼은 제거했습니다. 하나의 일반 일정이 명확히 일치하면 바로 취소하고, 후보가 여러 개면 선택합니다. 반복은 이번만/선택 회차 및 이후/전체 반복을 확인합니다. 취소한 일정은 캘린더·알림·충돌 검사에서 제외합니다.

Google 이벤트 ID가 있으면 먼저 Google 삭제 성공을 확인한 뒤 로컬 취소를 기록합니다. 여러 회차 중 네트워크 실패가 나면 이미 성공한 취소는 유지되고, 실패한 회차와 나머지는 유지됩니다. 다시 같은 문장으로 남은 후보를 확인할 수 있습니다.

### 일반 단어와 개인 사전

- 집·본가·병원·치과·회사·도서관 등은 뜻이나 주소를 묻지 않습니다.
- 집에서 운동=운동, 병원에서 업무 미팅=업무. 명시적 활동이 장소 기본 분류보다 우선합니다.
- 종숲·구로숲 같은 모르는 별칭은 실제 이름과 선택적 주소, 카테고리를 확인합니다. 기억 체크를 끄면 이번만 적용합니다.
- 나의 규칙에서 개인 사전을 수정·삭제할 수 있습니다.
- Gemini 프롬프트도 일반 단어/별칭 구분과 활동 우선 규칙을 적용했고, 일반 장소 오질문을 서버 후처리로 보완했습니다. 장소 검색이나 모델 재학습은 아닙니다.

### 규칙 및 알림

나의 규칙에서 일정 사이 여유 시간, 운동 종료 시각, 주말 업무 차단, 카테고리별 알림 시간을 설정합니다. 기존 알림함은 예약 정보 미리보기로 구현했습니다. Google 동기화 시 popup reminder 설정도 전송하지만, 브라우저 자체의 백그라운드 푸시는 아직 없습니다.

## 검증과 남은 범위

자동 검증: 기존 엔진 79개 + 통합 테스트 5개, TypeScript 검사 및 Expo 웹 export. 실제 브라우저 조작, Android/iOS, Gemini 호출, Google 계정 실동기화는 별도 확인이 필요합니다.

- 일정과 규칙은 이 브라우저 저장소에 있습니다. 기기 간 공유와 서버 일정 DB는 아직 없습니다.
- 충돌 검사는 이 앱에 저장된 일정만 대상으로 합니다. Google의 기존 일정을 조회하여 비교하는 기능은 아직 없습니다.
- 여러 날짜에 걸친 기간 일정은 기존 캘린더에 유지하며, 일정 비서는 하루 일정과 유한 반복만 등록합니다.
- 복잡한 문장은 Gemini API가 필요합니다. 로컬 파서는 모든 한국어 문장을 이해하지 않습니다.
- Google 생성 요청은 네트워크 응답이 유실되면 중복 여부를 확정할 수 없습니다. 실제 서비스에는 서버 idempotency와 동기화 재시도 큐가 필요합니다.
- Google 연결의 기존 단일 사용자 구조 및 서버 권한 검사는 공개 출시 전 해결해야 할 사항입니다.
