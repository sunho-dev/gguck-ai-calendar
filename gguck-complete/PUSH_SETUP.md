# 실제 알림 연결

이 업데이트는 서비스 워커, 기기 구독, 서버 예약 저장, 예약 발송 API를 포함합니다.
파일만 교체했다고 실제 푸시가 켜지는 것은 아닙니다. 다음 설정은 프로젝트 소유자가 배포 환경에 해야 합니다.
`npm run web`은 화면 서버이며 Vercel API를 실행하지 않습니다. 실제 연동 검증은 Vercel 테스트 배포에서 진행합니다.

## 1. 서버 환경변수

기존 Upstash Redis의 `KV_REST_API_URL`, `KV_REST_API_TOKEN`을 사용합니다.
`npx web-push generate-vapid-keys`로 한 번 생성한 키를 Vercel에 저장하세요.

| 변수 | 값 |
| --- | --- |
| VAPID_PUBLIC_KEY | 생성한 publicKey |
| VAPID_PRIVATE_KEY | 생성한 privateKey, 서버에만 저장 |
| VAPID_SUBJECT | 운영자 연락처, 예: mailto:본인이메일 |
| CRON_SECRET | 충분히 긴 무작위 비밀값 |
| GEMINI_API_KEY | 자유 문장 규칙 해석에 쓰는 기존 서버 키 |
| AI 모델 | 기존 일정·일괄 일정·규칙 해석 모두 api/_interpretCore.ts의 MODEL (`gemini-3.6-flash`) 사용. GEMINI_MODEL 환경변수로 재정의하지 않음 |

키 생성 결과를 저장소에 커밋하지 마세요. 이 작업에서는 실제 키 생성·배포를 하지 않았습니다.

## 2. 예약 실행

스케줄러가 매분 `GET https://배포주소/api/push?action=cron`을 호출하도록 설정합니다.
헤더는 `Authorization: Bearer CRON_SECRET값`입니다. 비밀값을 URL에 넣지 마세요.
Vercel Pro에서 Cron을 사용한다면 기존 vercel.json에 다음 crons 필드를 추가할 수 있습니다.

```json
"crons": [{"path": "/api/push?action=cron", "schedule": "* * * * *"}]
```

Hobby에서 매분 실행을 지원한다고 가정하지 마세요. 매분 실행 가능한 외부 스케줄러를 연결하거나
지원하는 요금제를 사용해야 합니다. 기본 vercel.json에는 유료 스케줄을 넣지 않았습니다.
정각 전달은 OS·네트워크·실행 주기에 따라 늦어질 수 있습니다.

## 3. 사용자 연결 및 검증

1. HTTPS 배포에서 알림함 → ‘알림 연결하고 테스트’를 누르고 권한을 허용합니다.
2. 실제 테스트 알림이 도착하는지 확인합니다.
3. 5분 뒤 일정을 등록하고 알림을 시작 시각으로 설정합니다. 브라우저 창을 닫은 상태에서도 확인합니다.
4. 다른 일정을 등록한 후 시간을 변경하거나 취소합니다. 알림 예약 재동기화 성공 후 이전 시간에 알림이 오지 않는지 확인합니다.
5. 서버 로그에서 cron 호출과 sent/failed 응답을 확인합니다.

iOS에서는 지원 버전의 홈 화면 설치 웹앱 등 웹 푸시 사용 조건을 확인해야 합니다.
Google 알림과 꾹 푸시를 동시에 사용하면 각각 알림이 옵니다. Google 알림은 준비물 문구를 별도로 표시하지 않습니다.

## 저장·실패 정책

- 인증 토큰은 이 브라우저에서만 보관하는 256비트 무작위 기기 토큰입니다. 서버에는 해시를 키로 사용합니다.
- 전체 사용자 일정 DB가 아니라 이 기기의 구독 및 발송에 필요한 최소 예약 정보만 Redis에 저장합니다.
- 등록·수정·취소 시 전체 예약을 교체합니다. 네트워크 실패는 화면 상단에 표시하고 온라인 복귀 및 1분 간격으로 재시도합니다.
- 오프라인 취소는 서버에 반영될 때까지 이전 푸시가 올 수 있습니다. 발송 중 취소와 동시에 발생하는 알림을 회수할 수는 없습니다.
- 중복 발송 방지 키, 기기별 잠금, 종료된 구독 정리, 제한된 요청량을 적용했습니다.
- 푸시 전송 성공 직후 서버가 종료되면 재시도할 수 있습니다. 같은 알림 tag로 표시 중복을 줄이지만 정확히 한 번 전달을 보장하지 않습니다.
- 한 호출에서 최대 5개 기기, 기기당 최대 5개 전송을 처리합니다. 소규모 테스트용이며 사용량이 늘면 큐 워커로 분리하세요.
- 로그아웃 개념 대신 ‘이 기기 알림 끄기’로 서버 예약을 삭제합니다. 공유 PC에서는 사용 후 꺼 주세요.
- 최신 메인의 Google 연결·해제·가져오기 및 브라우저별 익명 ID 흐름은 그대로 사용합니다. 익명 ID 자체가 검증된 로그인 세션은 아니므로 공개 서비스 인증 설계는 별도 사항입니다.
