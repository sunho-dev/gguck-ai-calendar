ZIP의 `gguck` 폴더에는 전체 소스가 있습니다. 기존 프로젝트 위에 덮어쓰지 않고 별도 위치에 압축을 풀어 VS Code로 연 다음 `npm.cmd ci`, `npm.cmd run web`을 실행할 수 있습니다. 이 소스 폴더는 Git 저장소 이력을 포함하지 않습니다.

## 복원한 기능

- 입력창 옆 캘린더, 날짜 이동, 일정 종료 시각·장소·별칭·반복·알림 정보 표시
- 반복 방식 선택, 요일/매월 날짜 변경, 시작·종료일, 4주/12주 설정
- 회차별 충돌·등록 가능·건너뛰기 개수, 날짜별 다시 포함
- 오전/오후 선택 후 단일 일정 즉시 등록, 대체 시간 선택 등록
- 클릭 가능한 예시 문장과 웹 날짜·시간 선택기
- 카테고리별 알림 팝업 미리보기 및 알림 개수 표시
- 규칙 변경 즉시 저장, 개인 사전 수정 팝업
- 지원 브라우저용 WebMCP 검토 도구(자동 등록하지 않음)

## 확인 결과

자동 테스트 총 90개, 타입 검사, Expo 웹 export 통과. 실제 브라우저 자동 클릭 검증은 브라우저 실행 파일 다운로드 실패로 완료하지 못했습니다. Gemini·Google 계정 실연동도 이번 검사에 포함되지 않았습니다.

직접 확인할 때는 다음 순서로 볼 수 있습니다.

1. ‘내일 8시 집에서 운동’ → 일정 등록 → 오전 또는 오후 선택 → 추가 등록 버튼 없이 캘린더에 반영되는지 확인.
2. 같은 시간을 다시 입력 → 충돌 안내 → 대체 시간을 선택하면 등록되는지 확인.
3. ‘내일 오후 3시 공부’와 반복 ‘매주’ 선택 → 팝업에서 요일·12주·종료일 변경 → 회차 수 확인.
4. 반복 ‘매월’로 변경 → 31일 선택 → 없는 날짜의 달은 건너뛰는지 확인.
5. 나의 규칙에서 여유 시간·알림을 변경 → 다시 들어가도 설정이 유지되는지 확인.
6. 알림함에서 미리보기 클릭 → 카테고리별 메시지 팝업 확인.
7. ‘다음주 금요일 8시 종숲 ㄱ’ → 뜻 기억 → 개인 사전에서 수정·삭제 확인.
8. ‘공부 전체 반복 취소’ → 후보와 범위 확인 → 취소한 일정·알림이 사라지는지 확인.

## GitHub에 올리기

```powershell
git push -u origin fix/preview-feature-parity
```

GitHub에서 base `main`, compare `fix/preview-feature-parity`로 PR을 만들면 됩니다. 최신 main과 겹치는 수정이 있다면 충돌 해결 후 병합해야 합니다. 이 결과물은 원격 push나 PR 생성을 수행하지 않습니다.
